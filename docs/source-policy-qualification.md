# Source-policy qualification at publication

A source qualification is trusted operator metadata. It is not a campaign
request field or a client-supplied expected policy hash.

Generate the private receipt using the reviewed `qualify_accuracy_source.py`
and normal native `qualify_source` operation. The installed SourceGuard
authenticates the scientific revision and source closure before the real
scientific `policy_fingerprint()` runs. Keep the generator receipt's exact
canonical bytes; do not copy a context policy pin into a new record.

For publication, the trusted activation guard may contain
`source_qualification_receipts`, a mapping from each **enabled qualified**
context ID to the SHA-256 of its exact generator receipt. Supply those private
files with repeated `--qualification-receipt PATH` arguments. Paths do not
establish trust: the guard's reviewed byte pins do. The publisher checks the
receipt schema, qualified context ID, runtime-profile and adapter pins, and
the complete source qualification record. Missing, extra, duplicated, changed
or aliased receipts fail before any policy update.

An unchanged enabled legacy context whose qualification is absent remains
loadable with the field absent and its original ID. It needs no invented
receipt and is not eligible for new work: the backend still rejects new
admission before reserving funds. The publisher's existing guarded live-policy
read also rejects newly added or newly enabled unqualified contexts. Disabled
historical contexts remain available for reconciliation and archival.

This publication check does not migrate campaigns, rewrite historical pins or
release unresolved costs. Actual source qualification generation, private
context/registry activation, backend or worker publication, and any corrected
campaign require their separate owner gates. No real qualification is
generated by the source-only tests.
